# الدين التقني — SSR الجزئي وأثره على SEO

**الحالة:** مفتوح — يُعالج في المرحلة 5  
**التاريخ:** 2026-11-24  
**السياق:** بعد المكوّن 5 (خريطة المسار) أصبح `dist` عند 58.73MB من 60MB، وهدف `index.html` أقل من 15KB.

## 1) القرار الحالي

اعتمدنا استراتيجية **SSR جزئي** للحفاظ على حدود الأداء:

1. **Sidebar:** الـ SSR يرسم المرحلة النشطة فقط داخل HTML. بقية المراحل الـ19 تُبنى بعد hydration على العميل. السبب: كل مرحلة إضافية تضيف روابط وأيقونات SVG إلى كل صفحة من صفحات الدروس الـ435.
2. **الصفحة الرئيسية:** يُرسم في SSR:
   - Hero
   - الإحصائيات
   - أول 3 مزايا
   
   وتُحمّل الأقسام السفلية بشكل غير متزامن عبر `IntersectionObserver` + `defineAsyncComponent`:
   - آخر 3 مزايا
   - RoadmapPreview
   - StartFromYourLevel
   - WhyThisSite
   - Footer
3. **الأيقونات:** مكونات Lucide تُرسم SVG داخل HTML. استيراد فردي فقط، بدون مكتبة كاملة.
4. **إعداد VitePress:** `themeConfig.sidebar` أصبح غلافًا مصغّرًا فقط لكي يعمل هيكل VitePress. القائمة الحقيقية تأتي من `sidebar.ts` عبر `CustomSidebar`.

## 2) التأثير على SEO

### صفحات الدروس
- محتوى الدرس نفسه **SSR كامل**، أي أن النص الأساسي قابل للفهرسة.
- روابط `prev/next` موجودة في HTML لكل درس، ويمكن للزواحف تتبع سلسلة الدروس عبر المراحل.
- لكن HTML كل صفحة يحتوي فقط على روابط المرحلة النشطة؛ المراحل الـ19 الأخرى تُضاف بعد تنفيذ JavaScript.
- محركات البحث التي تنفذ JS (مثل Google) قد ترى الروابط بعد hydration، لكن ذلك يستهلك ميزانية الزحف ويؤخر الفهرسة. المحركات التي لا تنفذ JS لن ترى هذه الروابط.

### الصفحة الرئيسية
- الأقسام السفلية (آخر 3 مزايا، خريطة المسار، ابدأ من مستواك، لماذا الموقع، الفوتر) غير موجودة في HTML الأولي.
- روابط الفوتر المهمة (GitHub، الترخيص، خريطة المسار) غائبة عن الزواحف غير المنفذة لـ JS.
- Hero والإحصائيات وأول 3 مزايا موجودة في SSR، لذا الرسالة الأساسية والرابط إلى أول درس موجودان.

### نواقص إضافية
- لا يوجد `sitemap.xml` أو `robots.txt` مخصص بعد.
- لا يوجد JSON-LD (Course / Organization) بعد.
- لا توجد صفحة 404 مخصصة أو خريطة روابط HTML.

## 3) الحلول المقترحة للمرحلة 5

### الحل 1: SSR كامل مع CSS masks
**الفكرة:** إبقاء كل المراحل الـ20 وروابطها في HTML، لكن استبدال أيقونات SVG المضمنة بأيقونات CSS mask مبنية على SVG data URI في ملف CSS مشترك، أو SVG sprite يُحمّل مرة واحدة.

- **المزايا:** كل روابط التنقل في HTML؛ تحسين الزحف والفهرسة؛ إزالة ~16KB من SVG من كل صفحة؛ لا تغيير في السلوك البصري.
- **التحديات:** يجب إعادة قياس `dist` (حاليًا 56.65MB)؛ قد يلزم تقليل عدد العناصر المرسومة أو استخدام sprite؛ الحفاظ على ألوان الأيقونات في الوضعين الفاتح والداكن.
- **معيار القبول:** `dist < 60MB`، `build < 60s`، وكل دروس الـ435 قابلة للوصول من HTML الثابت.

### الحل 2: Prerender للصفحات الرئيسية
**الفكرة:** بعد `npm run docs:build`، تشغيل متصفح headless (Playwright/Puppeteer) على `/` و`/roadmap` وصفحات المراحل الرئيسية، وانتظار اكتمال الـ lazy loading، ثم حفظ DOM النهائي كـ HTML ثابت.

- **المزايا:** الصفحة الرئيسية كاملة للمحركات دون الحاجة إلى SSR كامل لكل صفحة درس؛ أقل تكلفة من الحل 1.
- **التحديات:** يضيف زمن بناء وخطوة نشر؛ يجب التعامل مع روابط الأصول وhydration؛ استبدال `index.html` بعد الـ build قد يؤثر على SPA hydration إذا لم يُنفذ بعناية.
- **بديل نشر:** توليد ملفات `*.seo.html` وخدمتها حسب User-Agent عبر CDN أو الاستضافة.

### الحل 3: Iconify مع lazy loading
**الفكرة:** استخدام Iconify offline bundle (مثل `@iconify-json/lucide`) مع مكوّن أيقونة واحد يعتمد على أسماء الأيقونات، وتحميل الأيقونات عند الظهور أو بعد hydration.

- **المزايا:** HTML أصغر بكثير؛ إمكانية SSR كامل للروابط مع أيقونات أخف؛ إدارة مركزية للأيقونات.
- **التحديات:** إضافة dependency وحزمة أيقونات؛ الحاجة إلى lazy hydration؛ قياس أثرها على زمن البناء وحجم الـ bundle.
- **بديل خفيف:** SVG sprite + `<use>` مع تحميل الأيقونات عند الحاجة.

### القرار: تعطيل `$` المفرد، إبقاء `$$`

- في `config.mts` يُستدعى `md.inline.ruler.disable('math_inline')` بعد `md.use(markdownItKatex, ...)`؛ لذلك **لا يُحلَّل `$...$` إطلاقًا**، ويبقى `math_block` (`$$...$$`) مفعّلًا للمستقبل.
- أُزيلت `escapeCurrencyDollars` وقاعدة `core.ruler` المرتبطة بها: لم تعد ضرورية بعد تعطيل inline math، وكانت هشة (تعتمد على أن الحالة لا تشكّل زوجًا صالحًا).
- تحقق: `$/M tokens` و`$input × 4000 +` و`A$AP Rocky` تظهر كنص عادي في HTML المبني؛ `$$E=mc^2$$` تظهر كمعادلة كتلية (`.katex-display`).
- ملاحظة: `$$` يجب أن يبدأ كتلة مستقلة (سطر يبدأ بـ `$$`)؛ الصيغة المضمنة داخل جملة لا تُعالَج. و`\(...\)` و`\[...\]` غير مفعّلين.
- تحويل الصيغ النصية/Unicode الحالية إلى LaTeX ممكن لاحقًا عبر سكربت تحويل + مراجعة يدوية؛ لا يفعله إعداد KaTeX وحده.
- لتوفير الميزانية استُخدمت خطوط KaTeX بصيغة **woff2 فقط**: 20 ملفًا (0.25MB) بدل 1.03MB لكل الصيغ، وCSS 22KB. تكلفة dist الفعلية **+0.27MB**. أُصلح أيضًا خط الكسور لأن Tailwind Preflight يصفّر عرض الحدود.
- المعادلات تبقى LTR داخل الصفحات RTL، والـ display centered مع `overflow-x: auto`.
